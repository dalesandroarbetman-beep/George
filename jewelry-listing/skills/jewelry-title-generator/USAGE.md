# 饰品标题生成 Skill 调用指令

其他 agent 连接 George 仓库后，使用以下指令调用本 Skill：

> 请使用仓库中的 `jewelry-listing/skills/jewelry-title-generator` Skill。这个任务只负责饰品标题生成，不执行自动上品、后台登录或商品提交。
>
> 我可能只发送图片，也可能同时提供 SKU 和商品资料。请按单个 SKU 独立处理：先识别图片中可确认的款式、造型、装饰材质和资料字段，再执行仿大牌、品牌/IP、受保护独特设计或设计专利风险判断。命中风险时输出 `PASS/禁止上架`，证据不足时输出 `风险无法确认`，两种情况都不要生成标题。
>
> 通过风险判断后，只使用资料、用户确认或图片清晰支持的关键词生成三套中文标题，第一套为优先方案。默认标题结构为“系列/风格 + 造型 + 装饰材质 + 款式 + 成色/主体材质”。资料缺少装饰材质但图片清晰显示为锆石时，可以加入“锆石”；不要擅自添加天然、人工、合成、镀层、纯度、品牌、授权、联名、原创、专利或夸大宣传词。颜色、场景、送礼、尺寸、重量和数量默认不加。用户明确要求英文时，再将选定标题翻译为不超过 80 个英文字符的版本。
>
> 输出必须包含：SKU（没有则写“未提供SKU”）、状态、风险摘要、三套标题、未使用关键词、新关键词、关键词来源和备注。图片不清晰或资料冲突时，保留待确认信息，不把推断写成已确认事实。

## 直接发图时的最简指令

> 请使用 `jewelry-listing/skills/jewelry-title-generator`，仅根据这张饰品图片生成标题。先做仿大牌/IP 风险判断，再输出三套中文标题；无法确认的材质或风险请单独标记，不要擅自补词。

完整字段和状态定义见同目录下的 `references/data-contract.md`、`references/risk-rules.md` 和 `references/material-rules.md`。

## 共同改进指令（轻量模式）

> 使用前先拉取 George `main` 的最新版本，并在结果中注明 Skill 的 Git 提交号。正常生成标题时不要直接修改 `SKILL.md` 或确认词库。只有在用户纠正结果、发现重复错误、发现有价值的新词、或风险判断存在争议时，才补充一条简短的 `rule_feedback`；普通案例无需反馈。反馈格式可以先写成：`改进建议｜案例｜问题｜事实｜建议｜置信度`。单个案例只作为候选；新词必须等用户或维护者确认后才能进入确认词库，标题规则至少需要两个独立案例或用户明确同意，风险/IP规则必须人工审核。需要改主规则时创建独立分支并提交 Pull Request 到 George 的 `main`，不要直接推送主分支；没有 GitHub 写权限就返回提案，不要反复重试。

维护者可以在需要时指定若干历史任务，让 agent 从这些对话中提取改进点并去重汇总；不得默认扫描或复制成员的私人对话。详细门槛和提案字段见 `references/collaboration.md`。
