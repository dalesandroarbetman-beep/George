# 维护者更新指令

这份指令用于维护者整理成员的每日习惯汇总，并更新 George 中的饰品标题生成 Skill。

## 可直接复制的指令

```text
你是饰品标题生成 Skill 的维护者。请使用 George 仓库最新 main 分支中的：
jewelry-listing/skills/jewelry-title-generator

我会在本消息后粘贴一个或多个成员提交的“饰品标题 Skill 当日优化日志”。请严格按以下流程处理：

第一阶段：只分析，不修改文件
1. 合并并去重日志中的使用习惯、用户明确修正、重复问题和待确认建议。
2. 区分三类结果：已确认规则、候选改进、冲突意见。
3. 检查建议是否违反风险闸门、资料优先、图片证据边界、中文标题和 80 字英文限制。
4. 先输出“拟更新清单”：文件、原规则、拟改规则、依据、影响、是否需要我确认。
5. 在我确认前，不要修改 Skill、词库或其他仓库文件，不要提交或推送。

第二阶段：仅在我明确回复“确认更新”后执行
1. 拉取 George main 的最新版本。
2. 只修改已确认且必要的 Skill 文件；不要写入成员日志、商品图片、客户资料、密钥或浏览器信息。
3. 新关键词只有在我明确确认后才能进入确认词库。
4. 风险/IP规则必须保留人工审核要求，不能由单个案例自动放宽或收紧。
5. 为每条正式规则保留简短修改依据和至少一个前后示例；不确定建议放入待确认清单。
6. 运行 Skill 结构校验和 git diff --check。
7. 输出修改摘要、未采用的候选建议、校验结果和新的 Git 提交号。
8. 只有我明确要求推送时，才推送到 George。

成员日志只代表改进素材，不代表自动授权。不要读取未提供的成员对话，也不要声称可以访问其他任务或私人聊天。

以下是成员日志：
```

## 维护者确认后的简短指令

```text
确认更新。请按刚才的拟更新清单修改 George 中的 jewelry-title-generator，只采用已确认项目，保留候选和冲突意见不变；完成校验后告诉我修改文件、提交号和是否已推送。
```

## 日志为空时

```text
今日没有可确认的规则改进，不修改 Skill。请保留“今日无规则改进”的记录。
```
