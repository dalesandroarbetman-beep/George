# 第一版架构

## 四层边界

1. **输入层**：Excel/JSON、SKU、可配置的货盘路径和复审根目录。只负责读取与字段别名归一化。
2. **准备层**：定位主图/尺寸图、复制到复审目录、整理可用素材和固定字段。源货盘始终只读。
3. **决策层**：尺寸硬闸门、单 SKU 范围判断、标题/IP/材质风险、缺图状态和新关键词记录。
4. **交付层**：写入带版本的 `上品包.json`、`审核清单.md`；浏览器/API 后台适配器是独立组件，仅在明确授权且 `submission.ready=true` 时读取上品包，批量填写、提交、立即下架并做一次结果核验。

## 状态机

```text
读取资料
  -> 主图/尺寸图检查
  -> [缺主图或尺寸图] 已暂停（硬闸门）
  -> 风险与字段检查
  -> [风险未确认/禁止] 已暂停
  -> 素材检查
  -> [仅缺模特/场景图] 标记待补，不影响资料、标题和风险检查
  -> 上品包完成
  -> [明确授权] 后台创建 -> 立即下架 -> 人工复审
```

`workflow_stage` 描述当前阶段，`hard_stops` 只记录不可继续的原因，`warnings` 记录提醒但不一定阻塞的事项，`submission` 是适配器唯一提交闸门。适配器只做字段映射和后台交互，不重新解释业务规则；更换后台只替换适配器。

词库采用开放式策略：已确认词可直接复用，商品资料中的新词照常进入标题，同时写入 `new_keywords` 和 `keyword_sources`；只有明确禁用词或风险规则才会阻止流程。候选词的确认或拒绝由后续词库维护工具处理，不在上品准备脚本中硬编码。

## 性能原则

- 网络盘只扫描已知商品图片根目录，并在找到主图和尺寸图后停止。
- 推荐先运行 `build_image_index.py` 建立索引；日常上品提供索引后只读索引，不再扫描网络盘。索引无命中时提醒并暂停，不自动回退全盘扫描。
- 复审目录只读取当前 SKU 的 `图片/` 或显式传入的 `asset_dir`，不递归历史批次。
- 本地准备完成后再进入浏览器，浏览器阶段不逐字段往返读取。
- 连接异常时停止，保留上品包和具体阻塞原因。
- 后台适配器调用只读上品包校验器；后台字段映射和结果记录属于适配器自身，不回流修改前置规则。
- 固定程序的 `generation_mode` 默认是 `rules-only`：缺少模特/场景图只记为待补，不调用 CreatOK；`external-optional` 仅作为外部模块接入标记，不是固定程序依赖。
- 每次运行分配新的批次目录和 `run_id`，处理日志采用 JSONL 追加方式，保证幂等重跑不覆盖历史。
