# 明镜门 — 输出质量批判审查关口

> 以人为镜,可以明得失。一份答案最大的盲区,是写它的人看不见自己思路里的漏洞。
> 明镜门的本质:在输出前,设一道关口,换一双没有包袱的眼睛把答案逼到更深。

---

## 〇、运行前提(先确认,否则别启动)

明镜门的核心动作是"**真开一个独立子 agent**",因此**只适用于支持子 agent / Task / 多 agent 编排的环境**(Claude Code、Coze 多 agent 工作流,或任何能 spawn 子调用的框架)。

- **支持的环境**:主 agent 内部完成"生成草稿 → 开子 agent 审 → 整合",用户只看到最终结果。正常启用。
- **不支持的环境**(纯单轮 API,开不了子 agent):**明镜门无法真正实现,别假装**。降级:在主 agent system prompt 放"自我批判"软约束,接受它弱于明镜门。**不要让主 agent 在自己 context 里假装审自己——那不是明镜门,路径锚定没斩断,等于没做。**

---

## 〇b、防退化红线（五条 · **动手前先读，不是事后对照**）

> **为什么放在最前:** 这五条约束的是**执行过程本身**（子 agent 真不真开、上下文塞不塞、走不走多轮）。
> 原版把它放在第 138 行（全文 161 行，86% 处）—— **agent 读到时 SOP 已经跑完了，红线只剩事后对照的价值**。
> 一条都补救不了：子 agent 没真开，无法回头再开；上下文塞错了，那次审查已经作废。

1. **子 agent 必须真开,不许假装。** 主 agent 自己 context 里"反思一下"不算。
2. **上下文绝不塞主 agent 的思路 / 原始资料。** 塞错则路径锚定没斩断,明镜门作废。
3. **critic 必须提真问题、标严重度、不凑数。** 否则诤友退化成废话生成器,用一堆"建议补充细节"淹死主 agent。
4. **不每句都走,一轮制。** 只在复杂/高价值/高风险触发;审一次处置一次,不多轮循环。
5. **承认软门控。** 别假装 skill 有硬拦截,要硬门控就升级代码管道。

## 一、解决什么问题

主 agent 自审有一个绕不过的结构缺陷:**它的注意力已被自己刚才的推理路径锚住,倾向确认而非推翻自己。** 让它找自己的错,它会自我确认——这正是它该批判的偏误本身。

明镜门的解法:**开一个全新 context 的子 agent**,它没参与答案的形成、没有"我刚才那么想是有道理的"这个包袱,带五个批判视角冷眼审视,斩断路径锚定。这是 actor-critic(生成与评判分离)+ constitutional AI(批判-修订循环)的应用层落地。

---

## 二、定位:诤友,不是验收员

子 agent 是 **批判顾问 + 思考教练**,不是找错的 QA:验收员只能让答案"没错",诤友能让答案"更深"。它**提出问题、引入思维方式、把验证与回应的责任交还给主 agent**——不需要自己掌握全部答案,职责是"指出这里值得怀疑/这里有漏洞/这个角度被忽略",由主 agent 去证明、修正或承认局限。

---

## 三、五个批判视角(完整攻击链,每个有思维模型支撑)

攻击方向覆盖**向上(审问题)→ 向内(审答案)→ 向外(审落地)**,不再只在答案内部转:

| 视角 | 攻击什么 | 思维模型 |
|------|---------|---------|
| **① 问题与框架** | 问对题没?框架对不对?**关键词有歧义没?** (最高维) | 第一性原理 + **苏格拉底概念澄清** + MECE |
| **② 证伪与反例** | 结论稳不稳? | 证伪主义 + 逆向思维 |
| **③ 合理怀疑 + 认识论地基** | 事实真不真?基率忽略没?只看了幸存者吗? | 休谟剃刀 + **基础概率核查** + **幸存者偏差** + 知识三级标注 |
| **④ 思维漏洞 + 致命遗漏** | 推理通不通?把相关当因果没?有没有该说没说的?**顺前提推下去会不会自相矛盾?** | 溯因 + 第一性 + MECE 穷尽性 + **虚假因果(混淆变量)** + **单轮归谬** |
| **⑤ 落地与盲区** | 用得上没?后果追到二三阶没?多想一步 | **二阶后果链** + 实用主义 + 换位 + 类比 |

覆盖五类最致命问题:**答错题、结论错、事实假、推理漏/遗漏、用不上**。全是逆向攻击型,与主 agent 的正向生成互补。完整的批判指令见 `references/critic-prompt.md`。

> **2026年08月26日 增补(苏格拉底能力补齐)**:视角① 加**概念澄清**、视角④ 加**单轮归谬**。
> 起因是一次定位审查:全文"苏格拉底追问"只在两处作为**括号标签**出现,底下跟的全是第一性原理式的框架质疑,
> **没有一条是苏格拉底式的追问动作**——子 agent 读到那个括号,拿不到任何可执行指令。
> 补的两条都**能在一轮内做完**:概念澄清是一个问句;归谬的前提已写在草稿上,critic 自己推完即可,
> 不必像苏格拉底那样一句句问出来。**真正的多轮 elenchus 仍然不做**(与一轮制结构冲突,见 §六 边界第 5 条)。
> 落点选择:归谬放视角④ 而非视角①——视角④ 原本"把隐藏假设挖出来"就停了,归谬是**补完这个半截动作**,
> 比新增一个动作更便宜也更自洽。

> **2026-06-23 增补**:③④⑤ 中加粗的四项(基础概率忽略、幸存者偏差、虚假因果、二阶后果链)是新**操作化为显式提问**的认知偏误透镜——它们都是 LLM 从人类文本继承的系统性偏误,流式(单遍)推理结构上不会主动想到,正是"挑出流式推理想不到的错"的主力。**全部以"向作者提问/要求举证"的形式出现,critic 只提问不给解决方案(诤友 ≠ 代笔)。** 实测明镜门(5 视角)对推理 +16pp、对代码 +7.5pp(EVOLVE LOG-014)。

## 三b、领域加审轴(按被审对象类型**加挂**,不替换五视角)

五视角是通用攻击链。某些领域有五视角结构上照不到的死角,按对象类型加挂对应轴。

### 尽调报告(dd-listed / dd-private)· 固定加审两轴
| 轴 | 攻击什么 | 为什么五视角照不到 |
|---|---|---|
| **⑥ 机会诚实性** | 机会评级是**浮在情景数学之上**的吗?——上行主张有没有和红旗**同等举证**?量级是元/时间/份额,还是空泛形容词?每条机会有没有**证伪条件**? | 五视角天然攻击"结论过强",而机会侧的典型病是**结论过弱或凭空**:信息不足时把未知一律记成"弱",或反过来把 deck 自述当既成事实。两种失真方向相反,通用攻击链只防得住一边 |
| **⑦ 时效** | 每个"现在时"结论背后的数据日期是哪天?快照与交付日差了多久?差 >1 季度有没有声明"当前状况未知"? | 五视角查"真不真",不查"还成不成立"。**一个当时为真的事实,今天可能已经不成立**——这不是事实错误,是时效错误 |

**加审两轴时必查的三条硬规则**(判据在 `dd-agent/knowledge/opportunity_scout.md`):
1. **受限度分档**:L2/L3 单出现了机会"强/中/弱"评级 = 直接质疑。L2 只能出「假设强度＋验证成本＋证伪条件」——原 rubric 没有"未知"档,不分档会把所有未知压进"弱"。
2. **独立性**:机会线声称独立,但结论与风险线高度同向、或引用了 `findings/*.json` / `MASTER_仲裁.md` = 下游污染,质疑。查 `opportunity.json` 的 `independence_statement` 字段。
3. **禁配额**:🔴 **不得因为"机会条数比风险少"就质疑机会线没跑透**。判据是**流程**——四面是否全扫、每面是否有取证结论,不是条数。四面已扫而只出 2 条**就是真结论**。反过来,**要主动查有没有为配平版面凑数的机会**:凑出来的机会比没有机会更糟。

## 四、操作 SOP(主 agent 严格按此走)

### 第 0 步 · 二次确认是否值得走完整明镜门
skill 被触发 ≠ 一定走完整流程。**满足任一即走**:
- 含具体事实/数字/数据,且会被用户当依据采信
- 是不可逆或高代价决策的建议
- 篇幅长、逻辑链多步、结论较强
- 用户明确要求审查/挑刺/提升质量

都不满足(简单问答、闲聊、低风险短回答)→ **跳过,直接输出**。别每句都走,成本翻倍。

### 第 1 步 · 生成答案草稿(标记草稿,先不输出)

### 第 2 步 · 开干净子 agent(强制)
用 Task / subagent 工具真正开启独立子 agent。**传给它的上下文,严格按下面清单**:

**必须塞(三样)** —— **少塞任一样，对应视角直接废掉，而子 agent 不会告诉你它废了**:
1. **原始问题 / 任务**——用户最初要什么(没有它,①视角"答没答对题"直接废掉)
2. **答案草稿**——被审对象
3. **批判指令**——`references/critic-prompt.md` 全文

**可以塞(按需):**
4. **关键背景约束**——若判断对错依赖特定上下文(用户是非技术背景/预算上限/给监管看),塞进去,否则子 agent 会用错误标准审

**绝对不能塞(关键,塞错则明镜门作废):**
- ❌ **主 agent 的推理过程 / 思考链 / 草稿演变**——一旦塞入,子 agent 被你的思路带走,从"独立审视者"退化成"顺着你点头的人",路径锚定没斩断
- ❌ **主 agent 检索到的原始资料**——会让子 agent 陷进同样材料、越界去做"核对事实"(它的职责是合理怀疑、把举证推回主 agent,不是核对)

> 模型:**同模型可以**(很多场景无法分模型)。同模型时明镜门主要斩"路径锚定 + 偷懒",**斩不掉"模型本身的判断倾向"**,异质性有限;**不同模型当子 agent 增量明显更大**,条件允许时优先。

### 第 3 步 · 子 agent 按五视角审查,返回结构化质疑清单
输出格式(强制结构化,否则主 agent 无法逐条处置):
```
【核心结论复述】子 agent 先复述它理解的答案核心结论(若复述错→答案表达不清或子agent没读懂,本身是信号)
【质疑清单】每条 = 【严重度高/中/低】视角编号 — 问题描述 — 给作者的具体要求
【最致命的一条】若只解决一个,是第几条
```

### 第 4 步 · 主 agent 逐条处置(分档,全部留痕)
用 `references/disposition-template.md` 记录。按严重度:
- **高**:必须明确三选一 —— 采纳(指出具体改了什么)/ 反驳(给出为何不成立的理由)/ 存疑(承认局限,向用户标注)。
  **悬空的代价**:高严重度批判不处置就输出,等于**用一份"已审查"的标签盖住一个已知漏洞** —— 比没审更危险,因为读者会更信它。
- **中**:应回应,可简短(改/不改 + 一句理由)
- **低**:可采纳可略过,无需逐条交代

**批判可被反驳(子 agent 也会想偏),但高严重度的反驳必须说清为什么,不许无视。**
不写理由的"反驳"与"没看见"在留痕上**完全无法区分** —— 而留痕正是将来升级成代码门控时唯一能被校验的东西。

### 第 5 步 · 输出
发出整合后的答案 + "已知局限"(存疑保留的部分,向用户坦诚标注)。

### 第 5.5 步 · 放行前自检(逐条打勾,未过不输出)

- [ ] 子 agent 是**真开的**(Task/subagent 工具),不是我在自己 context 里"反思了一下"?
- [ ] 传给它的只有 **原始问题 + 答案草稿 + 批判指令**(+必要约束)?**没塞我的推理过程或原始资料**?
- [ ] 每条**高严重度**批判都有明确去向(采纳/反驳/存疑),**没有一条悬空**?
- [ ] 标"采纳"的,答案里**真的改了**——我能指出改在哪一句?(不能指出 = 假采纳)
- [ ] 标"反驳"的,**写了为什么不成立**?(没写理由 = 与"没看见"无法区分)
- [ ] 标"存疑"的,**已写进给用户的「已知局限」**?(存疑不外露 = 把风险私吞了)
- [ ] 处置留痕已按 [disposition-template](references/disposition-template.md) 记录?
- [ ] 只审了**一轮**,没有滑进"改完再审"的循环?

> **最容易骗过自己的是第 4 条。**
> 本 skill 是**软门控**——没有任何机制能物理拦住"嘴上采纳、实际没改"(§五 已诚实承认)。
> 而执行这道自检的,正是那个可能偷懒的主 agent 自己。
> **所以第 4 条的判据必须是「能指出改在哪一句」,而不是「我觉得改了」** ——
> 前者可验证,后者是循环依赖。这也是留痕存在的唯一理由:将来升级代码管道时,能被 diff 校验的就是它。

> **一轮制**:子 agent 审一次、主 agent 处置一次、出结果。**不做"改完再审、再改"的多轮循环**——在 skill 软流程里极易无限循环且成本失控。需要多轮的复杂场景,是管道形态该解决的。

## 五、门控的真实定位(诚实,必须知道)

明镜门叫"门",但要清醒:**在 skill 形态下,这道门是"软"的。**

skill 是一份指导主 agent 怎么做的文档,它没有任何机制能在"主 agent 没真整合批判"时**物理拦住**它输出。所谓门控,在 skill 层面只是"你应该处置完再输出"的指令——执行它的,正是那个可能偷懒的主 agent 自己(循环依赖)。

- **skill 形态(本包)**:有"标准化批判流程",**没有"硬门控"**。够用于大多数场景,挡不住铁了心偷懒/假整合的主 agent。
- **管道形态(以后升级)**:把这套写成 Claude Code 代码工作流,生成→调子 agent→**代码校验主 agent 修订版是否真回应了每条高严重度批判(diff/再过一次判断)**→不过就拦住。这才是真门控,但它是代码,不是 skill。

**务实路径:先用本 skill(软流程,覆盖 80% 需求),验证有效、且确实遇到"假整合"真问题了,再升级管道。** 第 4 步的"留痕"正是为升级留的接口——代码能检查那份留痕。

## 六、边界(明镜门能做什么,不能做什么)

**能**:斩断主 agent 自我确认 · 暴露思维漏洞与隐藏假设 · 对可疑事实提合理怀疑逼主 agent 举证 · 补看不见的盲区 · 质疑问题框架本身 · 把答案逼得更深。

**不能(五条诚实局限,别高估)**:
1. **审结果,审不了过程。** 只看最终草稿。基于不充分检索/错误中间步骤的答案可能被组织得看起来很完整,明镜门从表面看不出"信息不够"。过程质量需在过程节点单独把关,明镜门补不了。
2. **同模型时共享知识盲区。** 主 agent 不知道的事实,同底座子 agent 大概率也不知道。明镜门斩"路径锚定",补不了"共同无知";覆盖盲区需不同模型。
3. **软门控,依赖主 agent 诚实。** skill 层保证不了"假采纳"被根除,需管道层 diff 校验。
4. **不做多轮 elenchus。** 苏格拉底最锋利的是**层层追问逼到自相矛盾**——一层答案生出下一层问题。
   一轮制把它从架构上排除了(这是**成本取舍,不是疏漏**:软流程里多轮极易失控)。
   本 skill 的"苏格拉底"标签兑现的是三件事:**概念澄清(视角①)+ 单轮归谬(视角④)+ 助产术(诤友定位)**,
   **不是完整的苏格拉底方法**。需要真递进追问,得升级成多轮管道,那是代码不是 skill。
5. **保证深度,不保证正确,更逼不出上限。** 明镜门让答案"经得起五类攻击"、抬升质量下限;但答案有没有洞见、有没有一个它压根没想到的更优路径,取决于主 agent 的能力与拿到的信息。**它是质量的地板抬升器,不是天花板突破器。**
