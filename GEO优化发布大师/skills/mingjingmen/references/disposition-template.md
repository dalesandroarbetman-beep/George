# 明镜门 · 主 agent 处置留痕模板

> 用法:主 agent 拿到子 agent 的质疑清单后,在内部按此模板逐条处置,再据此优化答案。
> 作用:① 强制留痕,防"嘴上承认实际不改"的假整合 ② 为升级成代码门控留接口——管道层可校验这份留痕是否每条高严重度都有明确去向、采纳项对应的答案部分是否真的变了。

---

## 处置表

| 批判# | 严重度 | 处置 | 说明 |
|:----:|:----:|------|------|
| 1 | 高 | 采纳 | 在答案"___"处改为"___"(指出具体改动) |
| 2 | 高 | 反驳 | 此质疑不成立,因为___(必须给理由,不许只写"无关") |
| 3 | 高 | 存疑 | 确属局限,无法在此解决,已在输出末尾向用户标注 |
| 4 | 中 | 采纳/不改 | 一句理由 |
| 5 | 低 | 略过 | (低严重度可不交代) |

**门控自检(放行前必过)**:
- [ ] 每条【高】严重度,是否都有明确去向(采纳/反驳/存疑)?有未处置的 → 回去处置
- [ ] 每条标"采纳"的,答案里对应部分是否真的改了?(防假采纳)
- [ ] "最致命的一条"是否已认真处理?

## 已知局限(附在最终输出末尾给用户)

> 把所有"存疑保留"的条目,坦诚汇总给用户,让人自行判断:

- 局限一:___(对应批判#__,为何无法解决,对结论的影响范围)
- 局限二:___

---

**一轮制提醒**:本模板用于一轮处置。处置完即优化答案并输出,不再让子 agent 二次审查。需要多轮的复杂场景,升级为代码管道处理。
