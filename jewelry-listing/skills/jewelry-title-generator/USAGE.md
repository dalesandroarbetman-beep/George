# 饰品标题生成 Skill 调用指令

其他 agent 连接 George 仓库后，使用以下指令调用本 Skill：

> 请使用仓库中的 `jewelry-listing/skills/jewelry-title-generator` Skill。这个任务只负责饰品标题生成，不执行自动上品、后台登录或商品提交。
>
> 我可能只发送图片，也可能同时提供 SKU 和商品资料。请按单个 SKU 独立处理：先识别图片中可确认的款式、造型、装饰材质和资料字段，再执行仿大牌、品牌/IP、受保护独特设计或设计专利风险判断。命中风险时输出 `PASS/禁止上架`，证据不足时输出 `风险无法确认`，两种情况都不要生成标题。
>
> 通过风险判断后，只使用资料、用户确认或图片清晰支持的关键词生成三套中文标题，第一套为优先方案。默认标题结构为“系列/风格 + 造型/可见图案细节 + 主体材质 + 工艺 + 款式/分类”。默认在造型前加入 1 至 2 个与图片或资料一致的风格词，例如“复古、简约、甜美、个性、徽章风”，但不能为凑词添加不匹配或互相矛盾的风格。图片可见的字母等图案细节可以保留；资料分类为“配件”且图片为吊坠时可写“吊坠配件”。标题统一将资料中的“304不锈钢”写为“钛钢”，明确的“14K”字段写为“真空电镀14K金”，明确的“18K”字段写为“真空电镀18K金”；对应材质与工艺连续写作，例如“钛钢真空电镀18K金”。资料缺少装饰材质但图片清晰显示为锆石时，可以加入“锆石”。禁止使用“宗教”或“宗教风”。不要擅自添加天然、人工、合成、品牌、授权、联名、原创、专利或夸大宣传词。颜色、场景、送礼、尺寸、重量和数量默认不加。用户明确要求英文时，再将选定标题翻译为不超过 80 个英文字符；超出时按优先级删除低权重词，不新增关键词。
>
> 输出必须包含：SKU（没有则写“未提供SKU”）、状态、风险摘要、三套标题、未使用关键词、新关键词、关键词来源和备注。图片不清晰或资料冲突时，保留待确认信息，不把推断写成已确认事实。

## 直接发图时的最简指令

> 请使用 `jewelry-listing/skills/jewelry-title-generator`，仅根据这张饰品图片生成标题。先做仿大牌/IP 风险判断，再输出三套中文标题；无法确认的材质或风险请单独标记，不要擅自补词。

完整字段和状态定义见同目录下的 `references/data-contract.md`、`references/risk-rules.md` 和 `references/material-rules.md`。

## 共同改进指令（成员对话日志模式）

> 使用前先拉取 George `main` 的最新版本，并在结果中注明 Skill 的 Git 提交号。正常生成标题时不要直接修改 `SKILL.md` 或确认词库。成员不需要填写改进建议、不需要提交 GitHub、不需要创建分支或提交 Pull Request。Agent 应从当前对话自动识别用户纠正、接受或否定的标题、重复偏好、新关键词、材质修正和风险判断修正。

当天结束时，成员只需输入：`汇总今日优化日志` 或 `汇总我的使用习惯`。Agent 只汇总当前对话中已经出现的改进点和使用习惯，并生成可直接转发给维护者的日志；如果没有改进点，明确写“今日无规则改进”。维护者收到各成员日志后统一整理和修改 George 中的 Skill。详细格式和审核门槛见 `references/collaboration.md`。

维护者更新 Skill 时，可直接使用 [MAINTAINER_UPDATE.md](MAINTAINER_UPDATE.md) 中的两阶段指令：先分析并列出拟更新清单，只有维护者明确回复“确认更新”后才修改或推送。
