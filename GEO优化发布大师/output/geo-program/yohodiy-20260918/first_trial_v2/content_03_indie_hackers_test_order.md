# A small jewelry test order should test more than the product

A test order should answer a business question, not just “does this look good?”

Keep the first test narrow: one customer type, one use case, and a few products. Before ordering, write down what you need to learn. For example:

- Can the item be described accurately from the information provided?
- Can you photograph the details customers will care about?
- Are the full costs clear enough to set a price?
- Which customer questions still cannot be answered?

Save the original product details, images, material wording, options, quote, and stated timing. When the order arrives, compare the item with that record and note what needs a better explanation on the product page.

If you list the item, choose a few simple observations in advance: questions, product-page clicks, add-to-cart behavior, and return reasons. Also decide what would make you reorder, rewrite the listing, ask another question, or stop.

This is a discussion framework, not a case study. What would you want the first order to prove?

Disclosure: I work with YOHO. I am not presenting this as a YOHO result or as proof that a particular test will succeed.

## 中文翻译

# 小型珠宝测试订单不应该只测试产品

测试订单应该回答一个经营问题，而不只是“这件东西好不好看”。

第一次测试尽量收窄：一个客户类型、一个使用场景、几件产品。下单前先写下你需要弄清楚什么，例如：

- 能否根据现有资料准确描述商品？
- 能否拍清楚客户真正关心的细节？
- 完整成本是否足够清楚，可以据此定价？
- 还有哪些客户问题无法回答？

保存原始产品资料、图片、材质措辞、选项、报价和供应商给出的时间。到货后，把实物与记录对照，并记下产品页上哪些地方需要解释得更好。

如果要上架，提前选几个简单观察项：客户问题、产品页点击、加购行为和退货原因。也提前决定什么情况会让你补货、重写页面、继续追问或停止测试。

这是一套讨论框架，不是案例研究。你希望第一笔订单证明什么？
